# update-docs — regenerate the skills documentation

**Arguments:** $ARGUMENTS

**Single source of truth: each skill's frontmatter.** `name`, `argument-hint`,
`disable-model-invocation`, and
```yaml
metadata:
  group: reflex | start | idea | know | decide | trust | organise | docs
  phrase: "One line, under ~25 words, no double quotes: what it does, in the user's terms."
```
Everything else is generated by `~/.claude/skills/lab/reference/gen_docs.py`.
Never hand-edit `SKILLS.md`, the README region between `<!-- skills:start -->`
and `<!-- skills:end -->`, or the PDFs — they get overwritten.

## Procedure

1. **Check for drift** (writes nothing):
   `python3 ~/.claude/skills/lab/reference/gen_docs.py --check`
   With `--check` in the arguments: report its output and stop.

2. **Fix what it reports, at the source:**
   - *no metadata.phrase / unknown group* → read that skill, write a phrase in
     the same voice as the others (what the user gets, concrete, no jargon it
     doesn't define), pick the group, add the `metadata:` block to its
     frontmatter. Don't touch the skill's body.
   - *not mentioned in GUIDE.md* → the guide is **curated, not generated**:
     add a row to the right table ("I have… → type → you get") and, if it
     changes a workflow, to "Typical flows". Keep the guide's voice.
   - A new group is a deliberate act: add it to `GROUPS` in `gen_docs.py`.

3. **Regenerate:**
   `uv run --quiet --with reportlab python ~/.claude/skills/lab/reference/gen_docs.py`
   → `SKILLS.md`, README table, `lab-reference.pdf`, `skills-reference.pdf`.

4. **Render-check the PDFs — look at them, don't assume.** Render each page to
   PNG (`uv run --with pypdfium2 --with pillow …`) into the scratchpad and read
   the images. Look for: a word or a trailing character wrapping onto its own
   line, a glyph showing as a box (the fonts lack some symbols — use a plain
   character instead), a section split awkwardly across pages, a table row
   overflowing. Fix in `gen_docs.py` (column widths, wording) and rerun.
   Say which pages were actually inspected.

5. **Hand-kept parts — check, don't regenerate:**
   - `reference/static_skills.json` — the bundled / synced / repo-local
     snapshot in `skills-reference.pdf`. Compare with the skills this session
     lists; update entries that appeared or vanished. Never document a command
     whose behaviour hasn't been verified.
   - README "Verified" table and "Decisions" — add a line if this change was
     tested or involved a design decision; never rewrite past entries.
   - Bump `version` in `.claude-plugin/plugin.json` when a **lab** skill was
     added, removed or renamed (minor) or changed behaviour (patch), then
     `claude plugin validate ~/.claude/skills/lab`.

6. **Report** — counts (personal / lab), what was regenerated, what drift was
   fixed at the source, what the render check found, and what's still manual.
   If a lab skill was *added*, remind: running sessions need `/reload-plugins`.

## Rules
- Docs describe what exists. If a skill is untested, the docs don't claim
  otherwise — the README's Verified table is the place that says which.
- Don't commit. Don't open the PDFs unless asked.
- If `uv` or `reportlab` is unavailable, still write the Markdown outputs and
  say the PDFs are stale.
